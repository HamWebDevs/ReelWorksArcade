# Future publication checklist

This is a private development build. No store submission, public repository or public release has been created.

- [ ] Playtest all three machines on the Galaxy S20+ / Android 13 and at least two smaller/larger modern ARM64 phones. Check taps, legibility, audio, Back navigation, interrupted process restoration, battery, sustained frame pacing and thermal behavior.
- [ ] Balance the generous free-play tables and persistent district/construction mechanics. Run multiple seeds and player strategies; use long-run uncertainty estimates before making any numerical return claim.
- [ ] Expand the shared decision panels into richer custom bonus presentations; add bespoke ladder art, more reveal choreography and cabinet material polish. Test reduced motion, flashing and contrast with users.
- [ ] Audit small utility buttons and all feature captions at phone size, Android font/display scaling and unusual screen ratios. Confirm screen cutouts and system gestures never obscure controls.
- [ ] Review all original names, artwork, app icon and store screenshots for trademark/trade-dress similarity; clear the intended product name in target markets. Preserve DejaVu and Godot notices.
- [ ] Choose a source/media licence and maintain a third-party inventory. Review generated media and provenance documentation before commercial distribution.
- [ ] Confirm current Google Play simulated-gambling, content rating, target-audience, age-rating, listing and regional requirements. Make the fictional/no-cash-value restriction clear in listing/screenshots as in-game.
- [ ] Maintain no payment, redeemable prize, advertising, tracking or gambling-service links. Reassess policies if scope ever changes.
- [ ] Create an accurate privacy policy/data-safety response reflecting local-only preferences and saves; audit the final APK/AAB for permissions and network dependencies.
- [ ] Create protected upload signing credentials outside Git; configure CI secrets, Play App Signing and reproducible release versioning. Follow ANDROID.md for an AAB. Do not reuse ephemeral debug keys.
- [ ] Verify current target SDK, minimum SDK, 16 KB native alignment, release signing, crash-free startup, offline behavior, installation and upgrades through an internal test track.
- [ ] Add a player-friendly module importer only after a schema/version/asset migration design and upgrade testing. Existing JSON modules are developer installed.
- [ ] Test save migrations and backup recovery before every update. Current schema is version 1; changes must preserve or explicitly migrate pending awards.
- [ ] Obtain the project owner's explicit authorization for any remote publication or store submission.
